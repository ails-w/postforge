# Arquetipo — Documentación y aprendizaje

> Base común: `hooks-psychology.md`, `recruiter-ats.md`, `linkedin-form.md`.

## Señales (detección)

- Repo mayormente markdown: guías, apuntes estructurados, mini-proyectos documentados.
- Plantillas propias, glosarios, roadmaps, análisis con referencias.
- Sin código ejecutable o con SQL/scripts de apoyo apenas.

## Hook recomendado

Fórmulas: **contraste** o **pregunta específica**. El valor está en el criterio, no en el código.

Forma: «Leer el capítulo no es entender el tema: estos N mini-proyectos me lo demostraron» / «¿Por qué el índice cubriente gana solo a veces?»

## Prueba que importa

| Prueba | De dónde sale |
|---|---|
| Artefacto concreto (guía, plantilla, análisis) | Repo |
| Resultado de un mini-proyecto | `analysis.md`, `development-log.md` |
| Antes/después de entender un concepto | Learning docs |
| Referencias citadas | `*-reference.md` |

## Media

| Pieza | Formato | Por qué |
|---|---|---|
| Principal | Portada con título + alcance (`matplotlib` o SVG) | Ubica el tema sin ruido |
| Secundaria | Diagrama del concepto o flujo (`mmdc`) | El concepto ES el producto |

## Aptitudes típicas (taxonomía)

`documentacion` (Markdown, Mermaid, docs de aprendizaje) · tema de dominio (`datos-y-sql`, `sistemas-linux`).

## Descripción del formulario

Qué tema (1 línea) → por qué importa / qué problema de aprendizaje resuelve (2-3) → enfoque (1) → artefacto producido (1).

## Evitar

- Presentar apuntes como producto terminado.
- Citar el libro/source sin aportar nada propio.

## Ejemplos del autor

`db-deep-dive-portfolio` (DDIA en mini-proyectos) · `lpi-linux-essentials-note` (apuntes + VM).
